Your Private Blockchain, One Click Away
💡 Welcome! Elyon Chain lets you create a fully functional Ethereum-compatible blockchain in minutes. Start fresh with your own chain, or connect to an existing one. Every step is guided — no blockchain expertise needed.
⛓️
1. Deploy Raw L1 POA (Vanilla)
Standard Proof-of-Authority Layer 1 chain. Single sealer signs every block. No L2 features, no APOS, no bridge — just a clean private blockchain you can use for development or as the starting point for the APOS conversion below.
🌐
2. Deploy APOS (L2) from POA
Same as (1) but pre-marks this chain as the L2 source for a future bridge. After the chain is producing blocks, run APOS Registry → PoS Conversion from the dashboard to bring up the full APOS fee-distribution stack.
📡
3. Deploy L2 Operator on APOS
Standard operator node. Syncs from an L2 admin via P2P, runs an open RPC. Optionally stake on APOS ElyonRegistry to earn the node share of every tx fee routed through your RPC.
🌉
4. Deploy L1 Miner on APOS (Hybrid Bridge)
Sync phase: pulls chain parameters from an existing APOS L2 (same chainId, same block period, same gas policy). Independence phase: runs as its own POA miner. Transaction-mirroring engages only after the two-way handshake (this node enters the L2 admin IP, the L2 admin enters this node's IP). Without the handshake the node keeps producing blocks as an independent L1.

⚠️ Chain frozen below transition block

Your conversion finished (staking contract deployed, validator staked) but block production hasn't crossed the PoS transition block. This typically happens if the PoA peers were disconnected before the chain reached the transition. Click below to rewrite the chainspec so the transition is the next block, then restart the node — your validator will mine the next block as PoS.

Last resort: Reset chain & start over

If "Activate PoS Now" doesn't unfreeze the chain after a few minutes, your sync-converted DB is hitting a state-root mismatch from the foreign PoA history (the original blocks contain Clique-style rewards in their state root, but our PoS engine doesn't replay rewards, so re-execution produces a different state). The fix is to wipe the chain DB and start fresh using the Create New Blockchain wizard path (which doesn't have this issue). This destroys the synced 1.28M blocks. Your validator key + admin password will need to be re-entered after reset.

📈 Tier Curve
The single fee-sharing policy for the whole chain: a validator's POOL (own stake + delegator deposits) selects its tier, which fixes its share of gas fees. Pool volume → transaction-fee share; APR comes only from staking packages.
💡 How it works: tiers are evaluated bottom-up — a validator gets the highest tier whose Stake ≥ threshold it clears. Rows must ascend by stake size. After saving a new curve, use ↻ Re-tier on the Validators tab to re-evaluate existing validators.
